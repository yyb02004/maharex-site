# 청첩장 통합 관리 · NAS 사진 폴더 업데이트

사진, 방명록, 참석 명단을 한 관리 화면에서 확인합니다. 하객 사진은 기존 저장소에 원본으로 보관하고, NAS의 **main → wedding → 하객사진** 폴더에도 자동으로 복사합니다. 기존 사진·방명록·참석 명단·인증서를 이어서 사용합니다.

## 먼저 기존 데이터 보관하기

업데이트 전에는 기존 `maharex-wedding-data`와 `maharex-wedding-tls-data` 볼륨을 백업해 두세요. 사진 폴더만 복사한 것은 방명록과 참석 명단을 포함하는 전체 백업이 아닙니다. 전체 백업이 필요하면 앱을 잠시 중지한 상태에서 두 볼륨을 보관합니다.

**기존 앱이나 볼륨을 삭제하지 않습니다.** NAS의 `main` 공유 폴더 전체 권한을 바꾸거나 새 앱을 추가할 필요도 없습니다.

## 1. 새 파일 복사하기

1. 전달받은 통합 관리 업데이트 ZIP을 PC에서 풉니다.
2. 파일과 `proxy` 폴더를 NAS의 **main → wedding**에 복사하고, 같은 이름은 덮어씁니다.
3. `Dockerfile`, `app.py`, `schema.sql`, `admin.html`, `photo_mirror.py`, `.dockerignore`가 **wedding 폴더 바로 안**에 있는지 확인합니다. 폴더를 한 겹 더 만들지 않습니다.
4. **하객사진** 폴더는 업데이트 과정에서 자동으로 준비됩니다. 이미 있다면 그 안의 다른 파일은 그대로 둡니다.

`.dockerignore`는 앞에 점이 붙은 파일입니다. 이 파일이 있어야 다음 업데이트 때 하객 사진 전체를 프로그램 빌드에 함께 읽어 들이지 않습니다. ZIP과 YAML에는 관리자 인증 설정이 있으므로 하객에게 공유하거나 공개 저장소에 올리지 않습니다.

## 2. 기존 composeqnap 앱 업데이트하기

1. **Container Station → Applications → composeqnap**을 엽니다.
2. **Edit 옆 화살표 → Recreate**를 선택합니다.
3. 준비된 **compose.qnap.manage.yaml**을 메모장으로 열어 전체 내용을 복사합니다.
4. Recreate 화면의 YAML을 전부 교체합니다. 관리자 비밀번호 설정과 볼륨 이름을 그대로 사용합니다. YAML의 `$$`도 정상 표기이므로 바꾸지 않습니다.
5. **Advanced Settings → Resources → Memory limit → Limited / 1024 MB**로 설정합니다.
6. **Validate → Update**를 누릅니다. 새 저장 서버 이미지를 만드는 동안 기다립니다.

HTTPS 서버는 NAS에 이미 설치된 이미지를 그대로 사용합니다. 새로 내려받거나 다시 빌드하지 않습니다. 공유기 포트나 인증서 설정도 다시 입력할 필요가 없습니다.

이번 구성에는 항목이 **세 개** 있습니다. 정상 완료 상태는 다음과 같습니다.

| 항목 | 정상 상태 |
| --- | --- |
| wedding-storage | Running / healthy |
| wedding-proxy | Running |
| wedding-photo-folder-init | Exited (0) 또는 정상 종료 |

마지막 항목은 **하객사진 폴더 권한만 준비하고 종료하는 일회성 작업**입니다. 멈춰 있어도 종료 코드가 `0`이면 정상입니다. 회사의 다른 폴더나 하객사진 폴더 안의 기존 파일 권한은 바꾸지 않습니다. 종료 코드가 `0`이 아니면 해당 항목의 Logs를 확인합니다.

## 3. 사진 폴더 확인하기

1. [청첩장 관리 화면](https://wedding-api.maharex.com/api/admin)에 관리자 비밀번호로 로그인합니다.
2. 사진 관리에서 NAS 사진 복사 상태를 확인합니다. 처음에는 저장된 사진 수에 따라 준비 시간이 걸릴 수 있습니다.
3. NAS **File Station → main → wedding → 하객사진**을 엽니다. 원본이 남아 있는 사진부터 이 폴더에 복사됩니다.
4. 복사가 완료된 사진 한 장을 내려받아 열어 봅니다. 폴더에 쓰지 못했다는 안내가 있으면 복사 상태와 `wedding-photo-folder-init`의 로그를 확인합니다.

관리 화면의 폴더 연결 확인은 실제로 임시 파일을 만들고 지우는 방식으로 검사합니다. NAS의 폴더 접근이 늦어지거나 실패해도 청첩장 업로드와 원본 보관은 기존 저장소에서 계속 처리되며, 폴더 복사는 다시 시도합니다.

**새 버전에서 받은 원본은 업로드된 파일 그대로** 복사합니다. 예전에 축소 저장된 사진은 원본을 복구할 수 없으므로 기존 축소본으로 구분됩니다. 사진 파일만으로도 필요한 장면을 찾을 수 있게 파일명을 붙이며, 같은 이름의 다른 파일을 임의로 덮어쓰지 않습니다.

## 4. 관리 화면 사용하기

- **사진:** 사진 확인, 개별·선택 삭제, 개별 다운로드, 전체 ZIP 다운로드.
- **방명록:** 남겨진 축하 글 확인과 삭제.
- **참석 명단:** 참석 응답 확인과 삭제, 전체 명단 CSV 저장.

삭제할 때는 화면의 대상을 확인하고 진행합니다. 사진을 삭제하면 청첩장의 공개 사진과 보관 원본이 지워지고, 자동 복사한 NAS 파일도 다음 동기화에서 지워집니다. 이미 PC에 내려받은 파일은 유지됩니다. NAS 폴더에 직접 넣은 다른 파일은 자동 삭제 대상이 아닙니다.

NAS 폴더의 파일을 직접 지워도 청첩장 사진은 삭제되지 않습니다. 관리 대상 사진이 남아 있으면 복사본을 다시 만들 수 있으므로 **사진 삭제는 관리 화면에서** 진행하세요. 전체 ZIP 다운로드는 회사 인터넷 업로드 속도와 사진 수에 따라 시간이 걸리며, 브라우저 다운로드 목록에서 완료를 확인합니다.

## 저장 위치와 권한

- 원본·사진 정보·방명록·참석 명단: 기존 `maharex-wedding-data` 볼륨.
- HTTPS 인증서: 기존 `maharex-wedding-tls-data` 볼륨.
- 자동 복사본: NAS **main/wedding/하객사진** (`/share/main/wedding/하객사진`).
- 인터넷 공개 사진: 촬영 위치 등 부가정보를 제거한 미리보기. NAS 복사본에는 원본 촬영 정보가 남습니다.

자동 복사 폴더는 기존 `main` 공유 폴더에 접근할 수 있는 NAS 사용자에게 보일 수 있습니다. 폴더 연결 작업은 이 폴더 하나만 준비하며, 프로그램은 계속 일반 사용자 권한으로 실행됩니다. 게스트 접근이나 회사 공유 폴더 전체 쓰기 권한을 켜지 않습니다.

자동 복사본에는 원본만큼 저장 공간이 추가로 필요합니다. NAS 여유 공간이 부족하면 관리 화면의 복사 상태를 확인하고 기존 보관 사진을 먼저 내려받습니다. 폴더 복사는 편의를 위한 추가 보관이며, 같은 NAS가 고장 나거나 원본을 삭제하는 경우에 대비한 별도 백업을 대신하지는 않습니다.
